# LLM 개발 에이전트 작업 지침

## 1. 목적

에이전트가 저장소 전체를 매번 읽지 않고도,
필요한 문서를 찾아 작은 범위로 안전하게 수정하도록 한다.

루트 `AGENTS.md`는 지도와 절대 규칙만 유지한다.
세부 정보는 문서 또는 가장 가까운 모듈의 `AGENTS.md`에 둔다.

## 2. 컨텍스트 로딩 순서

에이전트는 모든 작업에서 다음 순서를 따른다.

1. 루트 `AGENTS.md`
2. 작업 대상 파일까지의 경로에 있는 가장 가까운 `AGENTS.md`
3. 루트 문서 지도에서 관련 문서
4. 대상 모듈의 공개 API와 테스트
5. 실제로 변경할 파일

저장소 전체를 무작정 읽지 않는다.

## 3. 작업 유형별 필수 문서

### 새 기능

- `docs/PROJECT.md`
- `docs/ARCHITECTURE.md`
- `docs/DOMAIN.md`
- 대상 모듈 `AGENTS.md`
- `docs/TESTING.md`

### 인증·인가·개인정보·파일

- `docs/SECURITY.md`
- `docs/TESTING.md`
- 관련 ADR

### DB 변경

- `docs/DEVELOPMENT.md`의 마이그레이션 규칙
- 대상 모듈 데이터 모델
- 기존 migration
- 관련 persistence test

### API 변경

- `docs/API.md`
- 대상 Controller와 DTO
- 계약 테스트
- 공개 API라면 ADR

### 대규모 구조 변경

- `docs/ARCHITECTURE.md`
- `docs/decisions/`
- 새 ADR 초안

## 4. 에이전트가 먼저 확인할 것

구현 전 짧게 답할 수 있어야 한다.

- 어느 모듈의 책임인가?
- 변경되는 유스케이스는 무엇인가?
- 사용자는 누구이며 어떤 리소스를 소유하는가?
- 공개 계약이 바뀌는가?
- DB migration이 필요한가?
- 실패하거나 중복 실행되면 어떤 일이 생기는가?
- 보안 경계가 변하는가?
- 어떤 테스트가 실패해야 이 변경이 잘못됐음을 알 수 있는가?

답이 없으면 코드를 늘리기 전에 관련 문서 또는 ADR을 보완한다.

## 5. 구현 제약

에이전트는 다음을 하지 않는다.

- 새 프레임워크나 라이브러리를 근거 없이 추가
- 모든 계층에 인터페이스를 기계적으로 생성
- 요청 범위 밖 파일의 대량 포맷 변경
- 기존 migration 수정
- 테스트 삭제 또는 약화
- 보안 기능 비활성화
- Entity 직접 응답
- 사용자 ID를 요청 값으로 신뢰
- 예외를 삼키기
- 민감정보 로깅
- TODO만 남기고 완료 주장
- 실제로 실행하지 않은 테스트를 통과했다고 주장

## 6. 변경 크기

한 작업은 가능한 다음 단위로 제한한다.

```text
한 유스케이스
+ 필요한 도메인 변경
+ 필요한 migration
+ 테스트
+ 문서
```

여러 모듈을 동시에 크게 바꿔야 한다면
먼저 단계별 계획과 호환 전략을 작성한다.

## 7. 저장소 내 변경 기록

작업 완료 전에 다음을 확인한다.

- 현재 단계, 완료 항목, 진행 중인 작업, 다음 작업 또는 알려진 위험이
  바뀌었다면 `docs/PROJECT_STATUS.md`를 현재 상태로 갱신한다.
- 사용자 기능, 공개 API, 보안 정책, DB 스키마 또는 운영 방식이
  의미 있게 바뀌었다면 `CHANGELOG.md`의 `Unreleased`를 갱신한다.
- 중요한 기술 결정이 새로 확정되거나 기존 결정을 대체했다면
  ADR을 추가하거나 기존 ADR의 상태를 갱신한다.
- 단순 리팩터링, 오탈자, 포맷 변경, 테스트 이름 변경은
  `CHANGELOG.md`에 기록하지 않는다.
- 모든 파일 단위 수정 내용을 별도 일지에 반복하지 않는다.
  세부 diff와 커밋 단위 기록은 Git으로 관리한다.

## 8. 산출물 형식

작업 완료 시 다음을 요약한다.

```text
변경한 것
- ...

설계 이유
- ...

보안 영향
- ...

검증
- 실행한 명령과 결과

남은 위험 또는 후속 작업
- ...

문서 기록
- PROJECT_STATUS.md: 갱신함 또는 갱신하지 않은 이유
- CHANGELOG.md: 갱신함 또는 갱신하지 않은 이유
- ADR: 추가·변경 내용 또는 변경 없음
```

명령을 실행하지 못했다면 그 사실과 이유를 명시한다.

## 9. 로컬 AGENTS.md를 추가할 시점

다음 중 하나가 있을 때만 모듈 안에 추가한다.

- 모듈 고유 불변식
- 특별한 상태 전이
- 외부 시스템 계약
- 일반 규칙과 다른 테스트 명령
- 민감 데이터 처리 규칙
- 특정 파일을 변경할 때 반드시 함께 수정할 대상

단순히 루트 문서를 반복하기 위해 만들지 않는다.

## 10. 로컬 지침 예시

```text
src/main/java/com/example/livinghub/issue/AGENTS.md
```

이 파일에는 Issue 모듈의 상태 전이, 공개 API, 이벤트,
필수 테스트 위치만 적는다. 전체 프로젝트 규칙은 반복하지 않는다.

## 11. 문서 부패 방지

- 구현과 문서가 다르면 같은 변경에서 수정한다.
- 삭제된 경로를 문서 지도에 남기지 않는다.
- 루트 AGENTS가 길어지면 상세 규칙을 문서로 이동한다.
- 중복된 규칙은 한곳만 원본으로 두고 링크한다.
- 정기적으로 깨진 링크와 오래된 ADR 상태를 확인한다.
