# 프로젝트 전체 정의

## 1. 제품 비전

Living Hub는 자취 생활의 모든 정보를 무작정 모으는 서비스가 아니다.
사용자가 지금 확인해야 할 일과 다음 행동을 놓치지 않게 만드는
**개인 생활 운영 허브**다.

핵심 질문은 항상 다음과 같다.

> 오늘 무엇을 확인하고, 누구에게 연락하고, 언제까지 처리해야 하는가?

## 2. 해결하려는 문제

1. 생활 이슈의 처리 과정이 문자, 메모, 기억에 흩어진다.
2. 상대방 답변 대기와 내 행동 필요 상태가 구분되지 않는다.
3. 계약 통보기한, 월세 납부일, 식품 확인일 등 후속 시점을 놓치기 쉽다.
4. 같은 정보를 여러 앱에 반복 입력해야 한다.
5. 과거 문제의 해결 과정을 다시 찾기 어렵다.
6. 개인 데이터가 많은데도 범용 메모 앱은 소유권·보안 모델이 약하다.

## 3. 제품 원칙

### 행동 중심

기록보다 `다음 행동`, `담당 주체`, `기한`, `상태`를 우선한다.

### 연결하되 결합하지 않기

이슈에서 할 일과 지출을 연결할 수 있지만, 각 기능은 독립적인 모듈로 유지한다.

### 안전한 기본값

모든 개인 데이터는 기본적으로 비공개다.
인증만으로 접근을 허용하지 않고, 데이터 소유권을 매 요청마다 검증한다.

### 점진적 확장

초기에는 하나의 서버와 데이터베이스로 운영한다.
실제 병목이나 독립 배포 요구가 확인되기 전에는 마이크로서비스로 분리하지 않는다.

### 설명 가능한 자동화

자동 생성된 할 일과 알림은 어떤 기록에서 왜 생성되었는지 추적할 수 있어야 한다.

## 4. 목표 사용자

초기 사용자는 서비스 개발자 본인 한 명이지만,
데이터 모델과 권한 검사는 처음부터 다중 사용자 환경을 전제로 한다.

주요 상황:

- 자취방 시설 문제 관리
- 집주인·관리자·중개사와의 연락 추적
- 계약 만료 및 통보 일정 관리
- 고정비와 생활 이슈 비용 관리
- 냉장·냉동·해동 시점 기록
- 흩어진 후속 행동을 오늘 화면에서 확인

## 5. 핵심 사용자 흐름

### 생활 이슈 처리

1. 사용자가 이슈를 등록한다.
2. 중요도, 상태, 다음 행동, 확인일을 지정한다.
3. 처리 기록과 연락 기록을 시간순으로 추가한다.
4. 필요한 후속 할 일을 생성한다.
5. 대시보드에서 마감 임박 또는 기한 초과로 노출한다.
6. 해결 내용과 날짜를 기록하고 종료한다.

### 계약 관리

1. 거주지와 계약 정보를 등록한다.
2. 계약 종료일과 통보 기한을 계산하거나 직접 입력한다.
3. 시스템이 근거가 표시된 할 일을 생성한다.
4. 통보·협의·퇴실 준비 기록을 계약과 연결한다.

### 생활비 관리

1. 고정비와 변동 지출을 등록한다.
2. 생활 이슈 또는 계약과 비용을 선택적으로 연결한다.
3. 월별 예정 금액, 확정 지출, 남은 예산을 구분한다.

## 6. 범위

### MVP

- 회원가입·로그인·로그아웃
- 거주지 등록
- 생활 이슈 CRUD
- 이슈 처리 기록
- 상태와 중요도 관리
- 직접 할 일 생성
- 이슈에서 후속 할 일 생성
- 오늘·예정·기한 초과 대시보드
- 사용자별 데이터 격리
- 감사 가능한 주요 상태 변경 기록

### 2차

- 계약과 월세 일정
- 연락 기록과 메시지 템플릿
- 반복 할 일
- 이메일 또는 웹 푸시 외부 알림
- 파일 첨부
- 검색과 필터
- 생활비

### 3차

- 식품 보관 기록
- 데이터 내보내기와 삭제
- 모바일 친화 UI 또는 별도 클라이언트
- LLM 보조 기능
- 통계와 개인화

### 명시적 비범위

초기에는 다음을 만들지 않는다.

- 마이크로서비스
- 소셜 피드
- 결제 처리
- 의료·식품 안전 자동 판정
- 사람 대신 법률·계약 결론을 내리는 AI
- 자동으로 메시지를 발송하는 에이전트
- 사용자의 승인 없는 외부 시스템 변경

## 7. LLM 기능의 위치

LLM은 서비스의 핵심 규칙을 대신하지 않는다.
초기에는 개발 에이전트로만 사용하고, 제품 기능으로 도입할 때는
별도 모듈과 보안 검토를 거친다.

허용 가능한 후보:

- 처리 기록 요약
- 사용자가 작성한 연락 문구 초안
- 과거 유사 이슈 검색 보조
- 자연어에서 할 일 후보 추출

금지하거나 사람 확인이 필요한 동작:

- 사용자의 승인 없는 메시지 전송
- 식품 안전 여부의 확정 판정
- 계약의 법적 효력 확정
- 결제·삭제·권한 변경
- 원문 근거가 없는 사실 생성

## 8. 성공 기준

### 제품

- 오늘 화면만 보고도 당일 행동을 파악할 수 있다.
- 생활 이슈의 전체 처리 이력을 재구성할 수 있다.
- 기한이 지난 항목이 묻히지 않는다.
- 자동 생성 항목의 출처를 확인할 수 있다.

### 기술

- 새 기능을 독립 모듈로 추가할 수 있다.
- 모듈 경계를 자동 테스트한다.
- 사용자 간 데이터 접근이 차단된다.
- 마이그레이션만으로 빈 DB를 재구성할 수 있다.
- 주요 업무 흐름에 통합 테스트가 있다.
- 장애 원인을 로그와 메트릭으로 추적할 수 있다.

## 9. 단계별 로드맵

### Phase 0 — 기반

- 프로젝트 생성
- 환경별 설정
- PostgreSQL과 Flyway
- 오류 응답 규격
- 인증과 사용자 소유권 기반
- CI와 기본 테스트
- 모듈 경계 테스트

### Phase 1 — 생활 이슈

- 거주지
- 이슈
- 처리 기록
- 상태 전이
- 필터와 상세 화면

### Phase 2 — 행동 허브

- 할 일
- 이슈에서 할 일 생성
- 오늘/예정/기한 초과 대시보드
- 중복 생성 방지

### Phase 3 — 주거 운영

- 계약
- 통보 기한
- 월세 일정
- 연락 기록

### Phase 4 — 생활 확장

- 생활비
- 파일
- 식품
- 외부 알림

### Phase 5 — LLM 보조

- 별도 위협 모델
- 프롬프트와 출력 스키마 버전 관리
- 사용자 확인 단계
- 비용·품질·개인정보 평가
